# Geode Genesis: rules for Claude

Cozy mobile gacha sim for Android. Angular (standalone, signals, strict TS) + Capacitor. See README.md for the full design summary and stage plan.

## Workflow
- Work in stages (README). Finish and test a stage, then STOP and summarize before starting the next.
- Ask the user before any big decision not covered by the README/spec.
- Node >= 22.22.3 or 24 is required by the Angular CLI. Tests: `npm test -- --watch=false` (Vitest via `ng test`).

## Architecture rules (do not break)
1. **Pure pull logic.** `src/app/core/` has NO Angular/Capacitor/rxjs imports (enforced by `purity.spec.ts`). All randomness goes through the injectable `Rng` (`core/rng.ts`) so tests are deterministic.
2. **One config object.** `core/config.ts` (`GAME_CONFIG`) holds every number: costs, odds, luck, caps, pity, idle rate, daily bonus, shard values. Never hard-code these elsewhere (UI text must read from config too). Logic functions take `config` as a defaulted parameter so Remote Config (Stage 5) can override.
3. **Services** (`src/app/services/`): `GameStateService` (signals), `PullService`, `AdService`, `SaveService`. Screens talk to services, not to localStorage/AdMob directly.
4. **SaveService is an interface.** localStorage first, Firebase in Stage 5. Save format carries a `version` number (`GAME_CONFIG.saveVersion`) with migrations.
5. **AdService is an interface** with three implementations: Simulated (3-second fake dialog), AdMob (Google TEST ad unit IDs only), NoAds. The multiplier is granted ONLY after the reward callback fires.
6. **Ads never change pull odds.** Ads multiply coin rewards only (daily bonus, idle collection, post-crack bonus). Show "Ads are optional and never change your pull odds" wherever ads are offered.
7. Unit tests for all game logic.

## Injection tokens (src/app/services/tokens.ts)
`CONFIG` (active GameConfig), `CLOCK` (now in ms) and `RNG` are injectable so tests and Remote Config can swap them. Components read numbers from `GameStateService.config`, never from literals.

## Cloud (Stage 5)
Firebase JS SDK (lazy-loaded) behind `CloudBackend` (`services/cloud-backend.ts`); `FIREBASE_CONFIG = null` means local-only. Save is v2 (`savedAt`); newest save wins (`core/cloud-sync.ts`). Remote Config overrides are validated in `core/remote-config.ts` and can never touch ad ids, save version, level cap or slot counts. Setup: `docs/firebase-setup.md`.

## Game rules (quick reference)
- Currencies: **coins** (main), **shards** (duplicate at max level). Never call coins "gems"; gems are the characters.
- Luck = sum of crew gem luck, capped at +15%. Every non-Quartz weight x (1+luck), then ALL weights renormalized to 100%. At +3.5% luck: Quartz 59.17, Amethyst 28.58, Emerald 9.19, Ruby 2.55, Diamond 0.51 (unit test).
- Pity: Emerald+ guaranteed at 10 cracks, Ruby+ at 50; each counter resets when that tier or better drops (Ruby+ resets both). Ruby wins if both fire.
- Duplicates level a gem to 10; beyond that they convert to shards.
- Idle coins cap at 8 hours.
- Crew slots 4 and 5 are unlocked with shards (costs in `crew.slotUnlockShards`).
- Post-crack coin bonus is granted automatically; a rewarded ad adds the extra multiple.

## Art and style
- No image assets. Gems are SVG generated by a `GemArt` component seeded by gem id. Outline #24160F, stroke 2.5. Palette and rarity frames are in the README.
- Cave theme: bg #2A1C14, cards #3E2A1E / border #5C402D, nav #1E130D, stalactites #1C120C, text #F6E7D0, muted #CDB397, primary button gold #F2B84B (text #24160F), ad button amber #E8833A (text dark). Font Nunito 700/800. Keep accessible contrast.

## Out of scope for v1
Battles, PvP, story, hand-drawn art, real-money purchases, rate-up banners, seasonal events.
